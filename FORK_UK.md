# Опис форку Telegram Secure

> [!NOTE]
> [The English version of this documentation is available in FORK.md](FORK.md).

## Статус

Цей репозиторій є активним форком для розробки **Telegram Fork-Secure**. Він інтегрує протокол Signal Double Ratchet (`SecureOverlay`) із офіційним клієнтом Telegram Android. Збірки, які включають захищений оверлей, використовують бібліотеку `libsignal` під ліцензією AGPLv3; усі релізні пакети супроводжуються повним відповідним вихідним кодом та ліцензійними повідомленнями.

## Базова версія Upstream

- Базовий репозиторій Telegram: `https://github.com/DrKLO/Telegram.git`
- Назва віддаленого репозиторію: `upstream`
- Поточна базова версія upstream: **Telegram Android 12.10.5**
- Коміт злиття: `060c661c0 chore(upstream): merge official Telegram Android 12.10.5 into fork`
- Зафіксований коміт upstream: `dc780e81e` (`update to 12.10.5 (7105)`)

Оновлення з upstream заборонено вливати безпосередньо у робочі гілки. Синхронізація повинна відбуватися на окремих гілках оновлення з вирішенням конфліктів без послаблення криптографічних інваріантів та з обов'язковим проходженням інструментальних тестів.

## Межі продукту та архітектура

Telegram Fork-Secure суворо зберігає поведінку клієнт-серверного протоколу Telegram:

1. **Ізоляція від транспорту**: Модуль `SecureOverlay/` не залежить від мережевого транспорту. Він керує X3DH, Double Ratchet, криптографічним сховищем (Android Keystore) та серіалізацією корисного навантаження без імпорту класів Telegram та без виконання мережевих запитів.
2. **Адаптерні межі**: Інтеграція `TMessagesProj` із `SecureOverlay` здійснюється виключно через визначені адаптери:
   - `SendMessagesHelper`: Контролер відправлення, що гарантує шифрування лише дозволених захищених дій.
   - `ChatActivity`: Відображення захищених сесій, кодів безпеки (safety numbers), секретний рендеринг карт та діалоги попередження про спуфінг посилань.
   - `SecureLinkGuard`: Виявлення фішингу, омогліфів IDN та попередження про відкриття зовнішніх посилань.
   - `MessageObject` та `ChatMessageCell`: Декодування та відображення з локального кешу без витоку відкритого тексту на сервери.
3. **Принцип Fail-Closed**: Будь-який некоректний носій (malformed carrier), неочікуваний downgrade або помилка автентифікації відхиляється миттєво без зміни довіреного стану ратчета та без повернення до незашифрованого надсилання.

## Модель розробки та гілки

- **`dev`**: Основна гілка для щоденної розробки. Сюди спрямовуються PR після тестування.
- **`feature/<назва>`**: Гілки для розробки окремих функціональностей або багфіксів.
- **`main`**: Гілка стабільних релізів із тегами версій (`v<version>`).

## Локальне середовище розробки

Форк використовує відтворюване середовище NixOS у `shell.nix`:
- OpenJDK 21
- Android SDK платформи 35 і 36, build-tools 35.0.0 і 36.0.0
- Android NDK 27.2.12479018
- CMake 3.22.1

Збірка та перевірка ізольованого шару:
```bash
./scripts/check-local-mvp.sh
./scripts/build-local-mvp.sh
nix-shell --run 'ANDROID_SERIAL=<device> ./gradlew :SecureOverlay:connectedDebugAndroidTest --console=plain'
```
