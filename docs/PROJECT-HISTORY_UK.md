# Журнал історії проєкту Telegram Secure

> [!NOTE]
> [The English version of this documentation is available in PROJECT-HISTORY.md](PROJECT-HISTORY.md).

Цей журнал фіксує ключові рішення проєкту, пов'язані з безпекою, та підтверджувальні артефакти. Основним джерелом істини залишається історія Git та актуальна документація; цей журнал має виключно обліковий характер.

## 2026-08-11 — впровадження закритої бети та аудит продуктивності

**Подія:** Функціональність Fork-Secure була доопрацьована у форку клієнта Telegram для тестування на двох фізичних пристроях: захищене відображення 1:1 тексту та медіафайлів, режим «Збережені повідомлення», інтерфейс відновлення, локальний зашифрований кеш медіа та інтеграція переглядача/списків у стилі Telegram.

**Фактичні результати (Runtime):** Профілювання на пристрої RMX3491 з обмеженою пам'яттю виявило завантаження холодної історії захищеного чату в потоці інтерфейсу (UI thread). Цільовий попередній прогрів рушія (`engine prewarm`) зменшив виміряний час конструювання в основному потоці приблизно зі 176 мс до ~1 мс. Додаткові маркери трасування розділяють прогрів рушія, початковий та кешований оверлей, збережені повідомлення, відповіді та процес спарювання. Жоден маркер продуктивності не містить відкритого тексту, ключів, даних носіїв чи ідентифікаторів контактів.

**Статус безпеки:** Статус незалежного криптографічного аудиту залишається `CHANGES REQUIRED`. Локальні збірки та ручні перевірки на пристроях демонструють поведінку інтерфейсу, але не замінюють формального схвалення криптографії чи гарантій безпеки.

## 2026-07-21 — фіксація базового протоколу для аудиту

**Подія:** Зафіксовано базовий апстрім-коміт клієнта Telegram `9bcf3d2769c6d3f07105a992e5d9493e33ac3348` (`оновлення до 12.9.0 (6966)`) та підготовлено специфікацію **Telegram Secure overlay protocol v1, revision 1** для передачі на незалежний криптографічний огляд.

**Рішення:** `CHANGES REQUIRED`. Це виключно ревізійна базова лінія для аналізу.

**Артефакти та підтвердження:**
- [Запис форку](../FORK_UK.md) та фіксація апстріму.
- [Запит на аудит](protocol-review/REVIEW-REQUEST.md), [шаблон рішення](protocol-review/REVIEW-DECISION.md), [контрольний список](protocol-review/REVIEW-CHECKLIST.md) та [блокуючі питання](protocol-review/OPEN-ISSUES.md).
- Точні байти зафіксовано контрольними сумами в [REVIEW-ARTIFACTS.sha256](protocol-review/REVIEW-ARTIFACTS.sha256); процедура передачі описана в [REVIEW-HANDOFF.md](protocol-review/REVIEW-HANDOFF.md).
- Ізольована команда збірки `SecureOverlay` (`./gradlew :SecureOverlay:assembleDebug :SecureOverlay:testDebugUnitTest --console=plain`) успішно виконана на JDK 17.

**Чинний криптографічний шлюз:** `CHANGES REQUIRED` у [REVIEW-DECISION.md](protocol-review/REVIEW-DECISION.md).
