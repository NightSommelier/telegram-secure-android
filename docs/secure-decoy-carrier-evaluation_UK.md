# Оцінка маскувальних текстових носіїв (Decoy Carriers) у Fork-Secure

> [!NOTE]
> [The English version of this documentation is available in secure-decoy-carrier-evaluation.md](secure-decoy-carrier-evaluation.md).

**Статус:** виключно концептуальний дизайн. Канонічний носій `TGS1:` залишається основним за замовчуванням, доки цей режим не пройде огляд інтероперабельності, стійкості до пошкоджень та UX.

Утиліта KryptEY демонструє «fairytale mode», який стискає корисне навантаження, відображає кожні чотири біти в один із шістнадцяти невидимих символів нульової ширини Unicode (zero-width characters) та додає цей payload до видимого тексту-прикриття. Її документація також вказує, що перетворення HTML буфера обміну Telegram може пошкоджувати цю форму. Fork-Secure може уникнути меж буфера обміну, читаючи оригінальний рядок повідомлення Telegram безпосередньо, але він не може гарантувати, що кожна операція Telegram зберігає невидимі символи Unicode.

## Запропоновані межі

- Збереження наявного автентифікованого корисного навантаження libsignal без змін.
- Розгляд маскувального кодування виключно як зовнішнього транспортного представлення.
- Використання явного, канонічного маркера версії; заборона сканування довільного тексту на випадкові невидимі послідовності.
- Автентифікація повного режиму носія та видимого тексту-прикриття, щоб зловмисники не могли підмінити речення без виявлення.
- Відхилення обрізання, нормалізації, дубльованих маркерів, непідтримуваних кодових точок, надмірного розширення та хвостових невидимих даних.
- Розпізнаний пошкоджений носій повинен показувати помилку захищеного повідомлення і ніколи не відкочуватися до показу тексту прикриття як відкритого тексту відправника.
- Звичайний носій `TGS1:` залишається доступним для сумісності та відновлення.

## Необхідні тести Telegram

Тестування відправлення, отримання, редагування, прев'ю відповідей, пересилання, запланованого надсилання, сповіщень, оновлення реакцій, пошуку/індексації, копіювання, експорту та відображення в офіційному клієнті. Включення нормалізації NFC/NFKC, розбору сутностей, прев'ю посилань, серверного обрізання та клієнтів, які видаляють чи перевпорядковують символи нульової ширини.

Цей режим не може приховати метадані Telegram або надійно протидіяти аналізу трафіку. Видимий маскувальний текст також може вводити в оману користувачів непідтримуваних клієнтів, тому режим має бути добровільним (opt-in) для кожного чату та чітко позначатися всередині Fork-Secure.

Джерело: [KryptEY](https://github.com/amnesica/KryptEY), зокрема задокументовані формати сирих та fairytale повідомлень.
