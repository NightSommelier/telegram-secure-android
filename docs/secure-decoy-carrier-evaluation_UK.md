# Оцінка маскувальних текстових носіїв (Decoy Carriers) у Fork-Secure

> [!NOTE]
> [The English version of this documentation is available in secure-decoy-carrier-evaluation.md](secure-decoy-carrier-evaluation.md).

**Статус:** виключно концептуальний дизайн. Канонічний носій `TGS1:` залишається основним стандартом.

У деяких розробках (наприклад, KryptEY) демонструється режим «fairytale mode», який стискає корисне навантаження, транслює кожні 4 біти в один із 16 невидимих символів нульової ширини (Zero-Width Characters) та додає їх до звичайного видимого тексту-прикриття. 

## Запропоновані межі

- Збереження автентифікованого корисного навантаження libsignal без змін.
- Розгляд маскувального кодування виключно як зовнішнього транспортного представлення.
- Використання чіткого канонічного маркера версії.
- Автентифікація всього носія разом із видимим текстом обкладинки, щоб зловмисник не міг підмінити видимий текст без виявлення.
- При виявленні пошкодженого носія додаток повинен показувати помилку захищеного повідомлення і в жодному разі не відображати маскувальний текст як відкритий текст відправника.
- Канонічний формат `TGS1:` залишається обов'язковим для сумісності.
