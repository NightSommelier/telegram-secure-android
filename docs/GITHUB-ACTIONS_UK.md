# GitHub Actions: Збірка та релізи для різних архітектур

> [!NOTE]
> [The English version of this documentation is available in GITHUB-ACTIONS.md](GITHUB-ACTIONS.md).

Робочий процес автоматичної перевірки, збірки та публікації релізів налаштовано у файлі [`.github/workflows/android.yml`](../.github/workflows/android.yml).

---

## Етапи роботи (Jobs) та межі безпеки

Робочий процес розділений на дві ізольовані зони довіри:

### 1. Етап верифікації (`verify`)
- **Тригери**: Створення/оновлення Pull Request та пуші у гілки `dev`, `main`, `master`.
- **Права доступу**: Тільки для читання (`permissions: contents: read`).
- **Дія**: Компіляція production Java/Kotlin вихідного коду та інструментальних тестів `SecureOverlay` з використанням безпечних фіктивних значень (`TELEGRAM_API_ID=1`).
- **Ізоляція**: Сторонні Pull Request не отримують доступу до ключів підпису або бойових API-секретів і не збирають готові пакунки.

### 2. Етап пакування та релізу (`package`)
- **Тригери**: Пуші (не PR) у гілки `dev`, `main`, `master`, теги версій за шаблоном `v*`, або ручний запуск `workflow_dispatch`.
- **Права доступу**: Публікація релізів (`permissions: contents: write`).
- **Збірка 5 архітектур**:
  1. `universal`: Всі 4 ABI (`arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`) в одному файлі.
  2. `arm64-v8a`: Оптимізовано для сучасних 64-бітних процесорів ARM.
  3. `armeabi-v7a`: Для старіших 32-бітних пристроїв ARM.
  4. `x86_64`: Для Chromebooks, ПК та 64-бітних емуляторів.
  5. `x86`: Для 32-бітних емуляторів.
- **Верифікація цілісності**: Кожен APK проходить валідацію `aapt2 dump badging` та отримує файл контрольної суми `.sha256`.
- **Артефакти**: Зберігаються як workflow-артефакти протягом 14 днів.
- **Автоматичні релізи**: Для тегів `v*` скомпільовані файли автоматично додаються до відповідного GitHub Release.

## Необхідні секрети репозиторію (GitHub Secrets)

Для збірки підписаних production APK потрібні такі змінні:

| Назва секрету | Призначення |
| :--- | :--- |
| `TELEGRAM_API_ID` | Офіційний API ID додатку з my.telegram.org |
| `TELEGRAM_API_HASH` | Офіційний API Hash додатку з my.telegram.org |
| `RELEASE_KEYSTORE_BASE64` | Релізне сховище ключів PKCS#12, закодоване в Base64 |
| `RELEASE_STORE_PASSWORD` | Пароль до сховища ключів |
| `RELEASE_KEY_ALIAS` | Аліас ключа у сховищі |
| `RELEASE_KEY_PASSWORD` | Пароль до приватного ключа підпису |

Секрети записуються лише у тимчасові файли (`signing.properties`, `local.properties`, `keystore/release.p12`) із правами `umask 077` і гарантовано видаляються на фінальному кроці `always()`.
