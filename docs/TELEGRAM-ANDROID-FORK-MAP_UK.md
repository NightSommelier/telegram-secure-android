# Telegram Android Fork-Secure: Карта коду

> [!NOTE]
> [The English version of this documentation is available in TELEGRAM-ANDROID-FORK-MAP.md](TELEGRAM-ANDROID-FORK-MAP.md).

Цей документ слугує внутрішнім довідником для навігації по кодовій базі `telegram-secure-android/`. Нативні Secret Chats Telegram, канали та групові чати залишаються стандартними. Fork-Secure працює виключно у перевірених захищених 1:1 хмарних чатах та в окремому захищеному режимі «Збережених повідомлень» (Saved Messages).

---

## 1. Структура каталогів репозиторію

```text
telegram-secure-android/
├── TMessagesProj/                 # Код клієнта та бібліотек Telegram Android
│   └── src/main/java/org/telegram/
│       ├── messenger/              # Стан акаунта, повідомлення, медіаконтролери, БД
│       ├── tgnet/                  # TL-схеми, MTProto та мережевий транспорт
│       └── ui/                     # Екрани інтерфейсу, ChatActivity, клітинки, переглядачі
├── TMessagesProj_App/              # Пакування APK, маніфести, флейвори та конфігурація
├── SecureOverlay/                  # Ізольований протокол Signal та тести пристрою
│   └── src/main/java/org/telegram/secureoverlay/
├── docs/                           # Архітектурні описи, аудити безпеки та протоколи
├── scripts/                        # Скрипти перевірки оточення, збірки та деплою
└── keystore/                       # Локальні ключі та конфігурація підпису (ігноруються git)
```

Модуль `SecureOverlay` повністю ізольований від транспорту: він не повинен імпортувати класи Telegram або виконувати прямі MTProto-запити. `TMessagesProj` звертається до `SecureOverlay` через вузькі адаптери. Будь-яка нова функція спочатку повинна отримати канонічну серіалізацію та інструментальні тести в `SecureOverlay` перед інтеграцією в інтерфейс користувача.

## 2. Потік повідомлень, дій та посилань

### Вихідний потік (відправлення)

```text
ChatActivity / ChatActivityEnterView
    -> SendMessagesHelper (єдина точка перевірки)
    -> SecureChatEngine
       -> SecureContentCodec (тип та серіалізація корисного навантаження)
       -> SecureCarrierCodec (носій TGS1 у кодуванні base64url RFC 4648)
    -> Звичайний MTProto send у tgnet
```

`SendMessagesHelper` є головним контролером вихідних дій. Якщо дію не підтримано або сесія ратчета не активна, відправлення відхиляється (fail-closed) до звернення до мережі.

### Вхідний потік (отримання)

При отриманні Telegram зберігає непрозорий текст носія (`TGS1:...`). `ChatActivity` розпізнає маркер носія, викликає `SecureChatEngine` для розшифрування через сесію Double Ratchet та заповнює `MessageObject` розшифрованим текстом. Сервер Telegram бачить лише зашифрований конверт.

### Ключові точки входу: текст, дії та захист

| Компонент / Завдання | Файл / Шлях |
| --- | --- |
| Режим захисту, спарювання, прийом/відображення, діалоги посилань | `TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java` |
| Вихідні перевірки, редагування, пересилання, віддалене видалення | `TMessagesProj/src/main/java/org/telegram/messenger/SendMessagesHelper.java` |
| Клієнтське розпізнавання посилань, класифікація повідомлень, стан | `TMessagesProj/src/main/java/org/telegram/messenger/MessageObject.java` |
| Захист від спуфінгу посилань (IDN, Punycode, омогліфи, BiDi) | `SecureOverlay/.../SecureLinkGuard.java` |
| Серіалізація корисного навантаження (Текст, Контакт, Геолокація, Видалення) | `SecureOverlay/.../SecureContentCodec.java` |
| Пакування носія (конверт `TGS1:` base64url) | `SecureOverlay/.../SecureCarrierCodec.java` |
| Керування сесіями, спарювання, координація ратчета | `SecureOverlay/.../SecureChatEngine.java` |
| Сховище протоколу Signal у Keystore та зашифровані сховища | `KeystoreSignalProtocolStore.java`, `KeystoreEncryptedBlobStore.java` |

## 3. Потік медіа та розшифроване відтворення

```text
Вкладення користувача / Камера / Запис голосу та круглих відео
    -> SendMessagesHelper: класифікація фото/відео/голос/відеонотатка/аудіо/файл/стікер
    -> SecureContentCodec: формування автентифікованого маніфесту
    -> SecureMediaCrypto: шифрування байтів файлу з випадковим upload-іменем
    -> Telegram завантажує непрозорий файл + маніфест TGS1
    -> ChatActivity завантажує зашифрований файл -> розшифровує в обмежений кеш
    -> MessageObject спрямовує шлях до нативних компонентів відображення
    -> Нативне відтворення голосу, аудіо та відеонотаток прямо з кешу
```

Справжні імена файлів, типи MIME, підписи, розміри, тривалість, аудіохвилі та групування в альбоми належать до зашифрованого маніфесту. Поля сервера Telegram містять лише випадкові технічні ідентифікатори.

### Переглядачі медіа та захист екрана

- **Захист екрана**: Режим `FLAG_SECURE` програмно активується в `ChatActivity`, `ProfileActivity` та `PhotoViewer`, якщо увімкнено захист або секретний режим. Зняття скріншотів, запис екрана та мініатюри в диспетчері завдань заблоковані.
- **Захист від експорту**: Збереження розшифрованих фото/відео до галереї, завантажень чи пересилання незашифрованим контактам заблоковано в захищеному режимі.
- **Збереження аудіохвиль та тривалості**: Розшифровані голосові повідомлення, відеонотатки та аудіодоріжки зберігають форму хвилі та таймінги у `ChatMessageCell`.

## 4. Спеціальні кодеки корисного навантаження

- **Контакти (`TYPE_CONTACT`)**: Серіалізує ім'я, номер телефону та опціональну картку vCard у захищеному конверті; стандартний відкритий vCard Telegram очищується.
- **Геопозиція (`TYPE_GEO_LOCATION`)**: Серіалізує широту, довготу, точність та період live-трансляції; прев'ю блокує зовнішні мережеві запити до карт (`currentMapProvider = -1`) та вимагає згоди для відкриття в секретному режимі.
- **Дистанційне видалення (`TYPE_CONTROL_DELETE`)**: Криптографічно підписана команда; після отримання видаляє зашифроване повідомлення, локальний кеш у пам'яті та файли з диску.

## 5. Збережені повідомлення та резервне копіювання

Saved Messages працюють без сесії з віддаленим співрозмовником, використовуючи окремі сховища:
- `SecureSavedMessagesKeyStore` та `SecureSavedMessageCrypto`.
- Хмарні чернетки та прев'ю посилань суворо придушені в захищених Saved Messages.

Резервні копії ідентичності та історії розділені на два незалежні архіви:
- `SecureIdentityBackupCodec/Manager`: Ключі ідентичності та сесії.
- `SecureHistoryBackupCodec/Manager`: Локальні текстові записи та записи відображення.
- Після імпорту історії сесії залишаються на паузі до явного повторного підтвердження для уникнення атак повторного відтворення (replay).

## 6. Алгоритм розробки нової функціональності

1. **Визначення специфікації**: Додати канонічний тег та межі розміру в `SecureContentCodec`.
2. **Написання тестів**: Створити модульні та інструментальні тести для серіалізації, меж та помилок пошкодження даних.
3. **Реалізація в ядрі**: Інтегрувати шифрування/розшифрування в `SecureChatEngine` або `SecureMediaCrypto`.
4. **Вихідна перевірка**: Додати суворий валідаційний бар'єр у `SendMessagesHelper`.
5. **Інтерфейс користувача**: Реалізувати обробку в `ChatActivity` та відображення в `MessageObject`/`ChatMessageCell`.
6. **Верифікація на пристрої**: Провести тести на підключеному телефоні (`./scripts/check-local-mvp.sh`, connected tests).
