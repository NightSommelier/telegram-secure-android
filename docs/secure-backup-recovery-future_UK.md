# Безпечне резервне копіювання та відновлення — вимоги майбутніх версій протоколу

> [!NOTE]
> [The English version of this documentation is available in secure-backup-recovery-future.md](secure-backup-recovery-future.md).

**Статус:** ненормативні межі для майбутніх розробок. Цей документ не є частиною Secure Overlay v1 і не авторизує фінальне автоматичне резервне копіювання.

## Продуктове рішення

Майбутній реліз МОЖЕ дозволити користувачеві експортувати зашифровані дані відновлення під захистом пароля. Це ПОВИННО бути явним вибором користувача (opt-in), містити точний опис того, що відновлюється, та зберігати можливість видалення експорту. Автоматичне хмарне резервне копіювання Android Auto Backup та хмарні бекапи Telegram залишаються вимкненими для всіх захищених даних.

Архів, захищений лише паролем, є мішенню для атак перебором в автономному режимі. Додаток ПОВИНЕН чітко інформувати, що втрачений пароль відновити неможливо.

## Реалізований стан ручного архіву історії (`FSRK`)

Поточна тестова збірка містить реалізацію кандидата ручного експорту `FSRK`:

- Експорт включає глобальну ідентичність, зашифровані локальні тексти/контент та відомий список контактів для одного облікового запису Telegram;
- Активні сесії libsignal, довіра до контактів та розшифровані медіафайли виключаються з архіву;
- Відновлення замінює коріння захищеного сховища в одній транзакції та створює маркер відновлення, щоб після перезапуску процесу чати перейшли у стан очікування повторного спарювання;
- Кожен відновлений контакт ставиться на паузу до повторного спарювання та верифікації ключів;
- Спроби імпорту чужого акаунта, пошкоджених файлів чи імпорту поверх непорожньої інсталяції безпечно відхиляються без зміни наявного стану.
