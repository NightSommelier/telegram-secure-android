# Специфікація формату резервної копії ідентичності (Identity Backup) — чернетка 1

> [!NOTE]
> [The English version of this documentation is available in secure-identity-backup-format-draft.md](secure-identity-backup-format-draft.md).

**Статус:** локальний MVP для резервної копії виключно ідентичності (`FSBK`). Цей формат відновлює лише безперервність ідентичності користувача. Він не зберігає відкритий текст повідомлень, вкладення, медіафайли, сесії ратчета, паролі Telegram, чернетки чи логи.

## Модель загроз та відновлення

Архів захищає від втрати пристрою за умови збереження користувачем як самого файлу архіву, так і пароля до нього.

Відновлення вимагає входу під тим самим ідентифікатором Telegram та чистої інсталяції без активних захищених чатів. Відновлення одного архіву на кількох пристроях призводить до клонування сесій; контакти виявляють це через спеціальний протокол сповіщення про відновлення.

## Канонічний бінарний контейнер (`FSBK`)

Усі цілі числа мають порядок байтів big-endian (без знаку).

| Поле | Розмір (байти) | Значення |
| --- | ---: | --- |
| Magic | 4 | ASCII `FSBK` |
| Версія формату | 2 | `1` |
| KDF ID | 1 | `2` = PBKDF2-HMAC-SHA-256 |
| AEAD ID | 1 | `1` = AES-256-GCM |
| Прапорці (Flags) | 2 | `0` = захищено паролем, `1` = відкрито |
| Ітерації KDF | 4 | `600000` |
| Сіль (Salt) | 16 | криптографічно стійкі випадкові байти |
| Одноразовий номер (Nonce) | 12 | криптографічно стійкі випадкові байти |
| Шифротекст | довжина відкритого тексту | результат AES-GCM без тегу |
| Тег автентифікації | 16 | тег AES-GCM (128 біт) |

Асоційовані дані `AAD` охоплюють усі байти від `Magic` до `Nonce` включно.
PBKDF2-HMAC-SHA-256 формує 32-байтний ключ із пароля UTF-8 та збереженої солі.
