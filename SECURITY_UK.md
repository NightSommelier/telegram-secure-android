# Політика безпеки (Security Policy)

> [!NOTE]
> [The English version of this documentation is available in SECURITY.md](SECURITY.md).

## Статус

Telegram Fork-Secure — це дослідницький beta-форк для локального тестування та оцінки, а не публічний фінальний захищений месенджер. Додатковий режим Fork-Secure реалізований для звичайних 1:1 хмарних чатів і режиму «Збережені повідомлення» (Saved Messages); рідні Secret Chats Telegram залишаються незмінними.

Незалежний криптографічний аудит протоколу триває. Чинний статус аудиту залишається [`CHANGES REQUIRED`](docs/protocol-review/REVIEW-DECISION.md). Успішна локальна збірка, проходження модульних тестів або ручна перевірка на двох телефонах не є гарантією криптографічної неушкодженості. Не використовуйте цю збірку для передачі інформації, де порушення конфіденційності може спричинити серйозну загрозу чи шкоду.

---

## Повідомлення про вразливості

Категорично заборонено публікувати описи вразливостей, системні логи, мережеві носії (carriers), резервні копії, секретні ключі, паролі чи розшифровані вкладення у відкритих GitHub Issues, публічних чатах або git-комітах.

Про всі виявлені проблеми безпеки повідомляйте розробникам приватно через заздалегідь узгоджений безпечний позасмуговий канал зв'язку. У повідомленні зазначте:

- Точну версію APK чи хеш комміту вихідного коду, модель смартфона та версію Android;
- Мінімальні та безпечні кроки для відтворення проблеми;
- Очікувану поведінку на противагу фактичній;
- Чи зачіпає проблема відкритий текст (plaintext), криптографічні ключі, стан ратчета, резервне копіювання, автентифікацію або передачу медіафайлів.

## Межі безпеки та експлуатаційна гігієна

- **Захист від витоку облікових даних**: Ніколи не додавайте до git `local.properties`, API credentials, файли ключів підпису (`keystore/`, `*.p12`), резервні архіви, розшифровані файли або дампи пристроїв.
- **Принцип Fail-Closed**: Будь-який некоректний, пошкоджений чи повторний носій із префіксом `TGS1:` повинен відхилятися і за жодних обставин не може відображатися або передаватися як відкритий текст.
- **Захист екрана (Screen Protection)**: Режим `FLAG_SECURE` активний для вікон чату, профілю та переглядача медіа, якщо увімкнено захист екрана або секретний режим.
- **Безпека резервних копій**: Експортуйте резервні дані лише на зашифровані носії. Обов'язково перевіряйте відновлення на запасному тестовому пристрої.
- **Проблеми офіційного Telegram**: Уразливості, властиві базовому клієнту Telegram чи протоколу MTProto, слід також повідомляти через офіційний канал безпеки Telegram ([Telegram Security](https://telegram.org/security)).

## Межі аудиту протоколу

Будь-які зміни в мережевих форматах носіїв, парсерах, стані ратчета, життєвому циклі Android Keystore або взаємодії з транспортом Telegram вимагають оновленого криптографічного перегляду. Деталі дивіться у розділі [`docs/protocol-review/`](docs/protocol-review/) та на карті архітектури в [`docs/TELEGRAM-ANDROID-FORK-MAP_UK.md`](docs/TELEGRAM-ANDROID-FORK-MAP_UK.md).
